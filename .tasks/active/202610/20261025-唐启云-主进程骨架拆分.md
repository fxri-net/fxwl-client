# 主进程骨架拆分

计划位置：阶段二 契约与主进程 第 2 项；前置：契约层与配置 schema。

## 一、背景

`src/main/base.ts` 一个文件承载窗口创建、IPC 注册、端口探测、静态服务、配置读写全部职责，`src/main/index.ts` 又是入口与窗口逻辑混杂。职责不清导致任何一处改动都要读完整文件，也无法针对单块做测试。窗口尺寸与位置每次启动重置，二次启动会开出第二个窗口。

## 二、实施方案

- 拆 `src/main/index.ts`（单实例锁、生命周期）、`env.ts`（路径与开关）、`window.ts`（窗口创建与尺寸位置持久化）、`security.ts`（安全基线，本任务先留骨架）。
- 目录约定：`ipc/`（按域拆分，本任务先留空壳）、`service/`（静态服务、端口、配置读写）。
- `requestSingleInstanceLock`：未拿到锁则退出；`second-instance` 时恢复并聚焦已有窗口。
- 开发与生产的加载策略收敛到 `env.ts`，不再在窗口创建处分散判断。

## 三、影响范围

主进程文件结构；对外行为保持一致。⚠️ `base.ts` 拆分期间需保证 IPC 通道名不变，避免渲染层中途断联。

## 四、验证方式

- 冷启动正常，窗口可显示
- 重复启动第二个实例时聚焦已有窗口而非新开
- 调整窗口尺寸与位置后重启，恢复上次状态
- `pnpm verify` 通过

## 五、回滚方案

`git checkout -- src/main` 还原为单文件结构；已提交则按提交哈希回退。
