# IPC 域实现与静态服务重写

计划位置：阶段二 契约与主进程 第 5 项；前置：配置目录迁移 userData。

## 一、背景

IPC 通道仍按旧的对象字面量批量注册，参数无校验；静态服务与端口探测依赖 `netstat | findstr` 的命令拼接，只在 Windows 成立，且字符串拼接的命令在路径含空格或特殊字符时会解析错位。

## 二、实施方案

- `src/main/ipc/app.ts`：应用版本、重启、退出、打开配置目录。
- `src/main/ipc/config.ts`：配置读取、写入、重置、目录路径，全部经 schema 校验。
- `src/main/ipc/service.ts`：静态服务启停、状态查询、端口查询。
- `src/main/service/port.ts`：改用 `net.createServer` 探测，默认端口被占用时递增避让，跨平台一致。
- `src/main/service/static.ts`：基于 `http-server` 封装启停与状态，不做命令拼接。
- 全部通道按 `src/shared/contract.ts` 注册，注册器统一做入参校验与错误包装。

## 三、影响范围

主进程 IPC 与静态服务实现；渲染层调用点需同步改为契约方法。⚠️ 端口避让后实际端口需回传给渲染层，不能假设固定 2602。

## 四、验证方式

- 默认端口被占用时自动换端口，页面正常加载
- 服务启停重复调用幂等，无残留进程
- 非法入参被拒绝并返回结构化错误
- `pnpm verify` 通过

## 五、回滚方案

`git checkout -- src/main`；已提交则按提交哈希回退。
