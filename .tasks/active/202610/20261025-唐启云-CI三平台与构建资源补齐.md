# CI 三平台与构建资源补齐

计划位置：阶段一 工程基线 第 4 项；前置：ESLint 9 与 vitest 质量门。

## 一、背景

仓库没有 CI，任何改动都只能靠本机自检。`electron-builder.yml` 引用的 `build/notarize.js`、`build/icon_mini.ico`、entitlements 三个路径在仓库中均不存在，macOS 打包会在 `afterSign` 阶段直接失败；`publish` 指向 `example.com` 占位地址，属于会误导发布行为的残留配置。

## 二、实施方案

- 新增 `.github/workflows/ci.yml`，矩阵 windows / macos / ubuntu，统一执行 `pnpm verify`，Windows 额外跑一次 `electron-builder` 打包冒烟。
- 补齐 `build/` 资源：从仓库现有图标资源生成 `icon_mini.ico`；macOS 侧补 entitlements 文件；移除 `afterSign` 悬空引用或补齐 `notarize.js`，二者取一。
- `publish` 占位按发版策略处置（置空或改真实渠道），不在本任务引入自动更新能力。
- `electron-builder.yml` 的 `files` / `extraResources` 与实际产物目录核对一致。

## 三、影响范围

CI 与打包配置；不涉运行时代码。⚠️ 补资源或删 `afterSign` 后，macOS 产物的签名与公证行为会变化，需在 macOS 侧实跑验证。

## 四、验证方式

- CI 三平台全部绿
- 本机 `pnpm build` 后 `electron-builder --dir` 成功产出，无缺文件报错

## 五、回滚方案

删除工作流文件并 `git checkout -- electron-builder.yml`；已提交则按提交哈希回退。
