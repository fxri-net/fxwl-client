# 去隐式注入与 jQuery

计划位置：阶段三 渲染层 第 1 项；前置：IPC 域实现与静态服务重写。

## 一、背景

`unplugin-auto-import` 全局注入 `imApp`、`imStore`、`imView`、`doData`、`doParam`、`isXxx` 等标识符，任何文件都能直接使用而无 import 语句；jQuery 被挂到全局，实际只用到 `$.each`、`$.isPlainObject`、`$("#app")` 与按选择器删除节点。隐式全局使依赖关系无法静态分析，重构与删除都靠全文搜索，也是类型检查失效的根源。

## 二、实施方案

- 移除 `unplugin-auto-import` 配置与生成产物 `auto-imports.d.ts`。
- 移除 jQuery 依赖、全局注入与 `@types/jquery`。
- `src/renderer/src/libs/` 拆为 `is.ts`（类型判断）、`obj.ts`（克隆 / 合并）、`nav.ts`（跳转）三个纯函数模块，显式 import。
- `$.each` 改数组原生方法，`$.isPlainObject` 改 `is.ts` 实现，`$("#app")` 相关改为原生 DOM 操作。
- 全量替换隐式标识符调用点为显式 import。

## 三、影响范围

渲染层全部文件；行为保持一致。⚠️ 字符串 DSL 形式的 `doData.merge("ref|mix")` 在 `obj.ts` 内保留同签名，避免本任务与状态重构互相纠缠。

## 四、验证方式

- 全仓检索无 `$.` 调用、无未 import 的全局标识符
- `pnpm dev` 三页可切换，交互无变化
- `pnpm verify` 通过

## 五、回滚方案

`git checkout -- src/renderer` 与 `package.json`；已提交则按提交哈希回退。
