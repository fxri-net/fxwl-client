# 契约层与配置 schema

计划位置：阶段二 契约与主进程 第 1 项；前置：CI 三平台与构建资源补齐。

## 一、背景

主进程用 `doEvent` 对象的键名批量注册 `ipcMain.handle`，通道名散落在对象字面量里，没有集中声明；preload 把整个桥暴露为 `object`，类型信息在跨进程边界处彻底丢失，渲染层可以拼任意通道名。配置侧没有 schema，配置项形状完全靠使用处约定，位置类配置甚至以内联 style 字符串存储。

## 二、实施方案

- 新增 `src/shared/contract.ts`：以 `域:动作` 形式声明全部通道常量，每个通道给出 `param` 与 `result` 类型，并提供零依赖的运行时入参校验函数。
- 新增 `src/shared/config.ts`：配置 schema（含 `NavConfig` 的 `anchor` / `offsetX` / `offsetY` / `idleOpacity`）、默认值、`version` 字段与 migrations 迁移链。
- 新增 `src/shared/defines.ts`：跨端枚举，含四角锚点 `NavAnchor`。
- migrations 覆盖旧数据：`back_btns` 四角 style 字符串映射为 `NavConfig`，未知取值回落默认。
- `src/shared` 不引入任何运行时依赖，主进程与渲染层共用同一份类型来源。

## 三、影响范围

新增共享层，暂不接入调用方；为阶段二其余任务与渲染层提供类型底座。

## 四、验证方式

- vitest 覆盖 migrations：四角字符串映射、缺字段补默认、未知值兜底
- 入参校验函数对越界 / 类型错参数返回错误
- `pnpm verify` 通过

## 五、回滚方案

删除 `src/shared/` 三个文件；该任务不改动现有调用点，回滚无连带影响。
