# 安全基线与 preload 纯桥

计划位置：阶段二 契约与主进程 第 3 项；前置：主进程骨架拆分。

## 一、背景

主进程窗口创建处 `sandbox: false`，未配置 CSP，未拦截 `will-navigate`，未设置 `setWindowOpenHandler`，也没有统一权限处理器；渲染层可通过通用 `shell` 通道执行任意系统命令，等同把主机的命令执行权交给了页面。preload 把桥整体暴露为 `object`，既无白名单也无类型。

## 二、实施方案

- `window.ts` 的 `webPreferences` 归位：`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`、`webviewTag: true`（受阶段四白名单管控）。
- `security.ts` 注册：生产环境经 `session.defaultSession.webRequest.onHeadersReceived` 注入 CSP，开发环境放宽以满足热更新。
- 拦截 `will-navigate` 与 `setWindowOpenHandler`，只允许应用自身源；外链一律拒绝并提示。
- 统一 `setPermissionRequestHandler`，默认全部拒绝。
- preload 改为白名单方法集合，类型取自 `src/shared/contract.ts`；删除通用 `shell` 执行通道及其调用点。

## 三、影响范围

窗口安全配置与 IPC 暴露面。⚠️ `sandbox: true` 后 preload 失去部分 Node 能力，仅保留 `contextBridge` 与受限 `ipcRenderer`，拆分时要逐一核对现有调用。

## 四、验证方式

- 渲染层构造任意命令调用失败，无对应通道
- 页面内点击外链不接管主窗口
- `pnpm verify` 通过，开发模式热更新仍可用

## 五、回滚方案

`git checkout -- src/main src/preload`；已提交则按提交哈希回退。
