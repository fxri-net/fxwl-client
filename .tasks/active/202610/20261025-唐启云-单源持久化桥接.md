# 单源持久化桥接

计划位置：阶段三 渲染层 第 3 项；前置：Pinia 三 store 重构。

## 一、背景

当前配置同时写入 localStorage 与主进程，两处没有仲裁规则：任一侧失败或被清空，另一方仍是旧值，重启后表现取决于读取顺序。`doParam.watch` 还给每个字段挂了独立 watcher，配置项增多后写放大明显。

## 二、实施方案

- 新增 `src/renderer/src/composables/useBridge.ts`：主进程为唯一真源，启动时经契约通道拉取配置并水合成 store。
- 变更采用 500ms 防抖整体回写，避免逐字段请求。
- 回写失败保留内存态并给出可见提示，不静默丢数据。
- 删除 `libs/base.ts` 中的 `doParam.watch` 与 `utils/store.ts` 中的 localStorage 读写。

## 三、影响范围

渲染层持久化通道；store 字段名不变。⚠️ 迁移窗口内旧 localStorage 数据不再读取，首次启动以主进程配置为准。

## 四、验证方式

- 修改配置后重启生效，且主进程配置文件同步更新
- 模拟回写失败时页面不白屏且有提示
- `pnpm verify` 通过

## 五、回滚方案

`git checkout -- src/renderer/src/libs src/renderer/src/utils` 并移除 composable；已提交则按提交哈希回退。
