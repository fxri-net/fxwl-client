# 变更集体系与历史 CHANGELOG 回溯

计划位置：阶段五 收口 第 2 项；前置：三平台打包回归。

## 一、背景

项目此前只靠 git 提交记录追溯变更，没有版本化的更新日志：仅在 2023 年打过 `v1.0.0` / `v1.0.1` 两个标签，此后至本轮改造的全部改动（配置目录迁移、契约分层、内嵌页白名单、悬浮导航胶囊等使用者可感知变化）都没有版本登记。本轮收尾需要一套可持续的变更集机制，以及一份能反映真实能力变化的更新日志。

更新日志条目须结合提交记录与代码实际实现整理，不能直接罗列提交标题。

另有历史遗留：`electron-builder.yml` 的发布占位仍指向示例地址，自动更新去留未定；三平台回归已确认产物未生成更新元数据文件，与「不做自动更新」的实际状态一致，需在配置层同步收敛。

## 二、实施方案

- 引入变更集体系（复用全局 toolkit 的 changeset 封装）：`.changeset/config.json` 开启私有包版本管理（客户端不发布 npm，需 `package.json` 补 `private: true` 配套），`baseBranch` 指向主干，内部依赖更新级别取 patch。
- `package.json` 补齐 changelog 系列脚本（记录变更 / 消费发版 / 仅格式化三档），版本号由 `1.0.1` 落到本轮目标版本 `2.1.0`。
- 历史回溯：按能力演进切分七段版本（见下表），逐段依据该时间窗内的提交记录与代码实际实现撰写条目，不照抄提交标题。
- 本轮变更集：把本轮工程化改动（文档站、双平台 CI、README 精简、依赖瘦身等）按「类型：描述」逐条登记，作为 `2.1.0` 块的来源。
- 自动更新收敛：删除无实际用途的发布占位，保持「不自动更新」的实际形态。

| 2.0.0 | 2026-09-11 ~ 2026-10-25 | 现代化主体：Electron 降至 22 保 Win7、契约分层与 IPC 白名单、配置目录迁移、内嵌页放行与安全策略、三 store 与路由、配置页 schema、ESLint 9 + vitest 与 CI |
| 2.0.1 | 2026-10-25 ~ 2026-10-26 | 交互与工程细节：悬浮导航胶囊、快捷键与鼠标侧键、品牌前缀统一、测试目录独立 |
| 2.1.0 | 本轮 | 工程化收尾：变更集体系、文档站、双平台 CI、README 精简、依赖瘦身 |

### 2.2 记法与口径

- 每个版本块含版本标题、发布日期行、按语义分组的条目；分组顺序固定为重大 → 新增 → 调整 → 优化 → 修复 → 文档 → 清理 → 依赖 → 其他。
- 条目只写使用者可感知的能力变化，实现细节（函数名、文件路径）不进条目。
- 历史块写完跑一次历史归一，避免条目间残留空行。

## 三、影响范围

新增 `.changeset/` 与 `CHANGELOG.md`；`package.json` 增加私有标记、版本号与 changelog 脚本；`electron-builder.yml` 删除发布占位。不改运行时代码。

## 四、验证方式

- 七段历史块的日期窗与能力主线与提交记录可对应，条目描述与代码实现一致
- `toolkit tasks check` 通过（含变更集条目前缀与列表标记检查）
- `pnpm verify` 通过

## 五、回滚方案

删除 `.changeset/` 与 `CHANGELOG.md`，还原 `package.json` 与 `electron-builder.yml`；已提交则按提交哈希回退。
