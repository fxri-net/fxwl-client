## 二、实施方案

- 用例迁到 `src/__tests__/`，文件名与被测模块同名。
- 用例内相对导入改为 `../shared/<模块>`。
- `vitest.config.ts` 的 `include` 指向 `src/__tests__/**/*.{test,spec}.ts`。
- `tsconfig.main.json`、`tsconfig.web.json` 中已失效的 `src/shared/**/*.test.ts` 排除项改为 `src/__tests__/**/*`，保留「用例由 vitest 单独运行、不进入类型检查」的原意。
- 后续新增用例统一放该目录，按被测模块命名；需要 DOM 时在文件头以 `// @vitest-environment jsdom` 单独声明。

## 三、影响范围

仅测试文件位置与工程配置；`electron-vite` 不引用该目录，构建与打包产物不受影响。

## 四、验证方式

- `npm run test` 用例全部通过，用例数与迁移前一致
- `npm run verify`（lint → typecheck → test → build）通过

## 五、回滚方案

仅文件移动与配置字符串修改，按提交哈希回退即可还原。

## 六、完成情况

# 业务前缀统一为 fx

计划位置：阶段五 收口前的命名收敛；前置：内嵌页交互增强。

## 一、背景

重构期沿用了 `fxy` 作为设计令牌、样式类名与内嵌页分区的前缀，与项目既有的 `fx` 业务前缀不一致。同一套代码里两种前缀并存，后续新增样式与模块时容易再漂移，故统一收敛到 `fx`。

## 二、实施方案

- 设计令牌：`--fxy-*` 改为 `--fx-*`，SCSS 变量 `$fxy-palette` 改为 `$fx-palette`，定义与引用同批改。
- 样式类名：`.fxy-layout` / `.fxy-panel` / `.fxy-header` / `.fxy-footer` / `.fxy-grid` / `.fxy-action` 改为 `.fx-*`。
- 选择器字符串：`libs/module.ts` 的 `appendTo = ".fxy-layout"` 随类名同步，保证 Element Plus 弹层仍挂在外壳内。
- 内嵌页分区：`CLIENT_PARTITION` 由 `fxy-client` 改为 `fx-client`。
- 历史归档不参与改名。

## 三、影响范围

纯命名替换，颜色、尺寸、布局数值不变。⚠️ 令牌漏改不会报错只会静默失效，需靠残留检索归零兜住；`appendTo` 与 `AppLayout` 类名不同步会导致弹层挂到 `body`、定位错乱。分区名变更后内嵌页会话态失效，首次打开需重新登录一次。

## 四、验证方式

- 全仓源码残留检索 `fxy` 为 0 条（`.tasks/archive` 排除在外）
- `npm run verify` 通过
- dev 冒烟：首页栅格与底栏样式正常、下拉弹层定位正常、客户端页胶囊与失败态正常、内嵌页可加载
- `pnpm exec toolkit tasks check` 零问题

## 五、回滚方案
