# 业务前缀统一为 fx

计划位置：阶段五 收口前的命名收敛；前置：内嵌页交互增强。

## 一、背景

重构期沿用了 `fxy` 作为设计令牌、样式类名与内嵌页分区的前缀，与项目既有的 `fx` 业务前缀不一致。同一套代码里两种前缀并存，后续新增样式与模块时容易再漂移，故统一收敛到 `fx`。

## 二、实施方案

- 设计令牌：`--fxy-*` 改为 `--fx-*`，SCSS 变量 `$fxy-palette` 改为 `$fx-palette`，定义与引用同批改。
- 样式类名：`.fxy-layout` / `.fxy-panel` / `.fxy-header` / `.fxy-footer` / `.fxy-grid` / `.fxy-action` 改为 `.fx-*`。
- 选择器字符串：`libs/module.ts` 的 `appendTo = ".fxy-layout"` 随类名同步，保证 Element Plus 弹层仍挂在外壳内。
- 内嵌页分区：`CLIENT_PARTITION` 由 `fxy-client` 改为 `fx-client`。
- 历史归档不参与改名。

## 三、影响范围

纯命名替换，颜色、尺寸、布局数值不变。⚠️ 令牌漏改不会报错只会静默失效，需靠残留检索归零兜住；`appendTo` 与 `AppLayout` 类名不同步会导致弹层挂到 `body`、定位错乱。分区名变更后内嵌页会话态失效，首次打开需重新登录一次。
