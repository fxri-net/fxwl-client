## 一、背景

焦点落在 guest 内部时，渲染层完全收不到键盘事件，`Esc` 与 `Alt+←` 无法触发返回；加载失败只有静态提示，没有恢复路径；鼠标侧键也没有接上浏览器习惯。

## 二、实施方案

- 主进程监听 guest 的 `before-input-event`，命中 `Esc`、`Alt+←` 时经契约通道下发渲染层，由渲染层决定后退或退出。
- 渲染层监听鼠标侧键（`button 3` / `button 4`）触发后退。
- `did-fail-load` 显示错误码与重试、退出两个动作，重试走 `reload`。
- 快捷键触发时胶囊恢复满不透明，给出视觉反馈。

## 三、影响范围

主进程事件转发与客户端页交互；不改变页面结构。⚠️ `before-input-event` 需排除输入框内的 `Esc`（如全屏控件），避免误退出。

## 四、验证方式

- guest 内按 `Esc` 与 `Alt+←` 可后退/退出
- 输入态下 `Esc` 不误触发退出
- 断网失败后可重试恢复
- `pnpm verify` 通过

- 主进程在 guest 的 `before-input-event` 中转发 `Esc` 与 `Alt+←`；`Esc` 先查 `document.activeElement` 与 `document.fullscreenElement`，输入态或全屏态交还页面，查询失败按输入态处理。

# 客户端视图重写

计划位置：阶段四 内嵌网页宿主 第 2 项；前置：内嵌页安全硬化。

## 一、背景

客户端页用 `$(".fxy-panel .box").remove()` 直接删 DOM 节点来结束内嵌页，webview 的销毁依赖 jQuery 选择器命中，节点被框架复用时会漏删或误删；页面也没有加载中与加载失败两种状态，断网时只有白屏。

## 二、实施方案

- 以 `v-if` 控制 webview 挂载，离开页面即卸载，宿主地址变化时重建。
- 加载过程给出进度或占位，`did-fail-load` 给出错误态与重试入口。
- 离开页面时同步清理 guest 会话与监听器，避免重复注册。
- 组件卸载钩子内做资源回收，不依赖 DOM 删除副作用。

## 三、影响范围

客户端页生命周期；不改变对外交互。

## 四、验证方式

- 反复进出客户端页无残留 DOM、监听器数量不增长
- 断网进入时显示错误态，恢复网络后可重试成功
- `pnpm verify` 通过

## 五、回滚方案

`git checkout -- src/renderer/src/views/client`；已提交则按提交哈希回退。

## 六、完成情况

客户端页改为状态驱动的内嵌页宿主：

- 模板用 `v-if="canLoad"` + `:key="boxKey"` 控制 webview 生命周期，键值由 `client.url_host` 与重建计数拼成，宿主地址变化或点击重试时整个 guest 连同节点一起被替换，不再用 jQuery 选择器删 DOM。
- `datas` 收敛为 `loading` / `error` / `rebuild` 三个字段，`did-start-loading`、`did-stop-loading`、`did-fail-load` 分别驱动状态；子框架失败与错误码 -3（导航被取消）不进入错误态。
- 新增状态面板：未配置地址时提示前往「配置 - 客户端」填写，加载失败时展示 `errorDescription` 与目标地址并提供「重试」，加载中显示旋转指示器。
- `leavePage` 只做路由跳转，内嵌页随组件卸载销毁；`electron.vite.config.ts` 补 `isCustomElement` 声明 webview，避免被当作未注册组件解析。

与方案的偏差：

- 未引入 `visible` 字段与 `await nextTick()`：`v-if` 与 `:key` 在同一 patch 内即可先卸载旧 guest 再建新 guest，多一次显隐切换没有额外收益。
- 未加 `onBeforeUnmount` 回收钩子：换页时组件已卸载，钩子内赋值不生效；渲染层无需要手工回收的资源，guest 由 Vue 卸载销毁，会话与监听器由主进程 `destroyed` 回调清理。

验证结果：

- `npm run verify` 通过：lint 无告警，node / main / web 三套 typecheck 通过，vitest 16 项通过，electron-vite build 成功。
- 编译产物中 webview 为真实元素（`createElementBlock("webview", …)`），三个事件以 `onDidStartLoading` / `onDidStopLoading` / `onDidFailLoad` 形式绑定。
- dev 冒烟：临时将入口指向 `/client/index`、宿主地址指向本地 2602 服务，冒烟服务收到 `GET /`，证明入口重定向、webview 挂载与安全白名单链路均生效；配置与临时文件已还原删除。

# 内嵌页安全硬化

计划位置：阶段四 内嵌网页宿主 第 1 项；前置：视图与样式重写。

## 一、背景

`webviewTag` 处于直接可用状态，页面里可以写任意 `<webview src>` 指向任意地址；没有 `will-attach-webview` 拦截，guest 也没有被强制安全属性，等于把标签当作万能浏览器使用。guest 与主应用共用默认会话，缓存与权限面完全打通。

## 二、实施方案

- `security.ts` 增加 `will-attach-webview`：只放行配置中的 host，其余 `event.preventDefault()`。
- 覆写 guest 的 `webPreferences`：`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`、`webSecurity: true`。
- guest 使用独立 partition 会话，退出客户端页时清理。
- 拒绝 guest 的权限请求与下载，外链按安全基线策略处理。

## 三、影响范围

内嵌页加载路径与拦截策略；正常站点加载不受影响。⚠️ 独立会话意味着 guest 的登录态与主应用隔离、首次进入需重新登录，需向使用者说明。

## 四、验证方式

- 非白名单地址被拒绝加载
- guest 内 `require` / `process` 不可达
- 白名单站点正常加载，登录态可保持
- `pnpm verify` 通过

## 五、回滚方案

`git checkout -- src/main`；已提交则按提交哈希回退。

## 六、完成情况

已完成（2026-10-25 23:44）。

- `security.ts` 增加 `will-attach-webview`：解析 `params.src`，只放行与配置 `client.url_host` 主机名一致且协议为 http / https 的地址，其余 `event.preventDefault()`；本次被拦下的地址若为外链则转交系统浏览器，与主窗口既有的外链策略一致。
- 同一回调覆写 guest 的 `webPreferences`：删除页面自带的 `preload`，强制 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`、`webSecurity: true`，并指定独立分区。
- guest 使用独立分区：`CLIENT_PARTITION`（`fxy-client`）落在 `src/shared/defines.ts`，主进程覆写偏好与渲染层 `webview` 的 `partition` 属性处于同一来源；分区不带 `persist:` 前缀，数据只留在内存。
- `did-attach-webview` 中补充会话与交互策略：guest 会话的权限申请与权限查询一律拒绝、`will-download` 直接阻止；guest 内的跨站跳转与 `window.open` 一律拦截并转交系统浏览器；guest 销毁时 `clearStorageData()`，退出客户端页即清理会话。
- 验证：`npm run verify` 全绿（lint 0 问题、typecheck node/main/web、vitest 16 项、electron-vite build 三块产物）；`npm run dev` 冷启动加 `ELECTRON_ENABLE_LOGGING=1`，进程无异常输出。
