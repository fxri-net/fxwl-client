# tsconfig 三分与类型基线

计划位置：阶段一 工程基线 第 2 项；前置：依赖清理与版本升级。

## 一、背景

当前只有一份 `tsconfig.json` 同时覆盖主进程、preload 与渲染层，三者的运行时能力差异被抹平：主进程与 preload 跑在 Electron 22 内置的 Node 16.17.1 上，没有 `Array.prototype.at`、`findLast` 等 ES2022 API，而渲染层跑在 Chromium 108 上可以自由使用 DOM 与新语法。单一配置既无法拦截主进程误用新 API，也让渲染层的 DOM 类型泄漏到主进程。

## 二、实施方案

- `tsconfig.json` 改为 solution 形态，仅用 `references` 汇总三份子配置。
- `tsconfig.web.json`：`src/renderer`，`lib` 含 DOM，`types` 不含 node。
- `tsconfig.main.json`：`src/main`、`src/preload`、`src/shared`，`lib: ES2021`，`types: ["node"]`，`module: CommonJS`（Electron 22 主进程不支持 ESM）。
- `tsconfig.node.json`：`electron.vite.config.ts` 与后续 lint / vitest 配置等工具链脚本，`types: ["node"]`。
- 路径别名与 `electron.vite.config.ts` 对齐，`@/*` 与 `@shared/*` 双向可用。
- `@types/node` 统一到 `^20` 单一版本，避免多版本类型互相覆盖。

## 三、影响范围

仅类型检查配置与别名解析；不改任何运行时代码。⚠️ `lib: ES2021` 会让主进程现存的新 API 用法暴露为类型错误，需就地改写，属预期收益。

## 四、验证方式

- `pnpm typecheck` 三份配置全部通过
- 在主进程临时写 `[].at(0)` 报类型错误、在渲染层同写法通过（验证后移除）
- `pnpm build` 通过

## 五、回滚方案

`git checkout -- tsconfig*.json`；已提交则按提交哈希回退。

## 六、完成情况

- `tsconfig.json` 改为 solution 汇总 `node` / `main` / `web` 三份子配置。
- 新增 `tsconfig.main.json`：覆盖 `src/main`、`src/preload`、`src/shared`，`target`/`lib` 锁 ES2021，`module: CommonJS` + `moduleResolution: node`，`types` 为 `node` + `electron-vite/node`（后者提供 `?asset` 导入声明），`@shared/*` 别名指向 `src/shared/*`。
- `tsconfig.node.json` 收窄为工具链配置（`electron.vite.config.*`、`eslint.config.*`、`vitest.config.*`），移出主进程源码。
- `tsconfig.web.json` 增加 `src/shared/**/*` 与 `@shared/*` 别名；`@/*` 保持指向渲染层。
- `package.json` 新增 `typecheck:main`，`typecheck` 改为 node → main → web 串行。
- 验证命令：`pnpm typecheck`、`pnpm typecheck:main`、`pnpm typecheck:web`、`pnpm build`；并用临时探针确认主进程写 `document.querySelector` 会报 TS2584、渲染层同写法通过（探针已删除）。
- 事实更正：原计划的「主进程 `[].at(0)` 报类型错误」不可达——`@types/node@20` 的 `compatibility/indexable.d.ts` 给 `Array` 等补了 `at` 声明，`lib: ES2021` 拦不住；该层防护改由 E3（ESLint9 质量门）的 `engines: 16.17.1` + `no-restricted-properties` 承担。
