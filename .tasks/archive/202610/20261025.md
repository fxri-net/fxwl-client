# 配置目录迁移 userData

计划位置：阶段二 契约与主进程 第 4 项；前置：安全基线与 preload 纯桥。

## 一、背景

配置目录被写死为可执行文件同级的 `../fxwl-local`。安装到 `Program Files` 或受管控目录后该位置通常不可写，首启即失败；同时该目录不在用户数据区，多用户共用一份配置，卸载与备份都无从预期。

## 二、实施方案

- 引入 `electron-store@8`（CJS，锁死大版本，10 为 ESM-only 与 Electron 22 主进程不兼容），数据落 `app.getPath("userData")`。
- 启动时检测旧目录（含其中的 `website` 子目录）：只读遍历、按缺失项复制、写入迁移标记；不删除旧目录。
- 迁移失败或目标不可写时回退为读旧目录，保证降级可用并记录告警。
- 配置读写统一收敛到 `src/main/service/store.ts`，其余模块不直接触达存储实现。
- 提供配置目录路径查询，供配置页展示。

## 三、影响范围

配置的物理位置与读写入口；既有配置键名保持不变以配合 migrations。⚠️ 旧目录若被用户手动改动，迁移后以新目录为准。

## 四、验证方式

- 存在旧目录时启动，配置项与 `website` 内容完整迁移
- 旧目录设为只读时仍可启动并读到最后一次配置
- 新目录写入后重启生效
- `pnpm verify` 通过

## 五、回滚方案

保留旧目录不动即可手工回退；代码侧 `git checkout -- src/main`。

## 六、完成情况

已完成（2026-10-25 22:49）。

- `env.ts` 拆出两个目录：`localDir` 改为 `app.getPath("userData")`，新增 `legacyDir` 指向历史位置（打包为可执行文件上级的 `../fxwl-local`，开发为仓库根），后者只用于迁移与降级读取。
- 新增 `service/migrate.ts`：`doMigrate.prepare()` 返回实际使用的数据目录。旧目录存在且未落标记时，先确认用户数据目录可写，再按 `config` / `website` 两个条目递归复制，已存在的文件不覆盖；全部成功才写 `.migrated` 标记，中途失败不留标记、下次启动重试。任何异常都只告警并退回旧目录，不阻断启动。旧目录全程不删除。
- `service/store.ts` 以迁移结果作为 `cwd`，配置仍写作 `config/config.json`，键名与结构不变；新增 `doStore.dir` 暴露配置目录，供配置页展示（IPC 暴露随「IPC 域实现」任务落地）。
- `service/static.ts` 静态目录改用 `mkdirSync(recursive)`，目录缺父级时也能创建。
- 事实说明：迁移在 `store.ts` 模块初始化时执行，因为 `index.ts` 在模块顶层就要读 `panel.window` 决定 HTTP 缓存开关，存储实例必须在此之前就绪。
- 开发模式同样迁移：旧位置是仓库根，启动后配置与 `website` 复制到用户数据区，仓库内旧文件原样保留。
- 验证：`pnpm run verify` 全绿（lint 0 问题、三份 tsconfig、vitest 16 条、electron-vite 构建成功）；`pnpm dev` 冷启动后 `%APPDATA%\fxwl-client` 下出现 `config/config.json`、`website/`（含 `index.html` 与 `assets`）与 `.migrated`，配置内容与旧目录一致，主进程与渲染层无报错。⚠️ 只读旧目录与目标不可写的降级路径未做破坏性实测，逻辑上走 catch 回退。

# 安全基线与 preload 纯桥

计划位置：阶段二 契约与主进程 第 3 项；前置：主进程骨架拆分。

## 一、背景

主进程窗口创建处 `sandbox: false`，未配置 CSP，未拦截 `will-navigate`，未设置 `setWindowOpenHandler`，也没有统一权限处理器；渲染层可通过通用 `shell` 通道执行任意系统命令，等同把主机的命令执行权交给了页面。preload 把桥整体暴露为 `object`，既无白名单也无类型。

## 二、实施方案

- `window.ts` 的 `webPreferences` 归位：`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`、`webviewTag: true`（受阶段四白名单管控）。
- `security.ts` 注册：生产环境经 `session.defaultSession.webRequest.onHeadersReceived` 注入 CSP，开发环境放宽以满足热更新。
- 拦截 `will-navigate` 与 `setWindowOpenHandler`，只允许应用自身源；外链一律拒绝并提示。
- 统一 `setPermissionRequestHandler`，默认全部拒绝。
- preload 改为白名单方法集合，类型取自 `src/shared/contract.ts`；删除通用 `shell` 执行通道及其调用点。

## 三、影响范围

窗口安全配置与 IPC 暴露面。⚠️ `sandbox: true` 后 preload 失去部分 Node 能力，仅保留 `contextBridge` 与受限 `ipcRenderer`，拆分时要逐一核对现有调用。

## 四、验证方式

- 渲染层构造任意命令调用失败，无对应通道
- 页面内点击外链不接管主窗口
- `pnpm verify` 通过，开发模式热更新仍可用

## 五、回滚方案

`git checkout -- src/main src/preload`；已提交则按提交哈希回退。

## 六、完成情况

已完成（2026-10-25 22:47）。

- `window.ts` 的 `webPreferences` 收紧为 `nodeIntegration: false` / `contextIsolation: true` / `sandbox: true`，`webviewTag: true` 保留（内嵌页容器依赖，阶段四再做来源白名单）。
- `security.ts` 补齐导航边界：`will-navigate` 只放行应用自身页面，外链先 `preventDefault` 再交系统浏览器；`setWindowOpenHandler` 一律 `deny` 并对外链转交系统浏览器；`setPermissionRequestHandler` 与 `setPermissionCheckHandler` 默认全部拒绝。自身页面前缀在模块级按 dev / prod 分别取开发地址与本地 `index.html` 的 `file://` 地址。
- preload 改为白名单纯桥：`NativeBridge`（`restart` / `quit` / `store` / `openFile`）挂到 `window.doNative`，删除 `electronAPI`、`api` 与 `process.contextIsolated` 分支；`@electron-toolkit/preload` 在沙箱预加载中无法 `require`，连同依赖一并移除。`index.d.ts` 改为引用共享桥类型，并补 `export {}` 避免全局脚本化。
- 删除通用 `shell` 通道（渲染层无调用点）与 `ipc/index.ts` 中对应 `child_process` 引用，页面失去任意命令执行能力；`src/shared/contract.ts` 新增 `OpenFileOption`（渲染层安全的对话框参数，不引用 Electron 类型）与 `NativeBridge`。
- 偏差说明：CSP 未走 `onHeadersReceived`。生产环境页面以 `file://` 加载，文档响应不经过 `webRequest` 拦截，改为在 `electron.vite.config.ts` 加 `doPolicy()` 插件，仅在 `command === "build"` 时把策略注入 `index.html` 的占位注释，开发模式保持放宽以兼容热更新。

- 验证：`pnpm run verify` 全绿（lint 0 问题、三份 tsconfig、vitest 16 条、electron-vite 构建成功）；构建产物 `out/renderer/index.html` 已带上注入的 `Content-Security-Policy` meta；`pnpm dev` 冷启动冒烟通过，主进程、沙箱 preload、渲染层均无报错。⚠️ 外链接管与权限拒绝属交互行为，需人工点验。
