# 常见问题

按「现象 → 原因 → 处理」组织。配置字段的完整含义见[配置说明](./config)。

## 内嵌页相关

### 内嵌页提示「尚未配置客户端地址」

页面地址必须是以 `http://` 或 `https://` 开头的完整地址。只填 IP、域名或路径都不算有效地址。

处理：到「配置项 → 客户端 → 页面地址（HTTP）」填写完整地址，例如 `http://127.0.0.1:2602`。

### 内嵌页加载失败，错误码怎么看

错误码来自 Chromium 网络栈，常见几类：

| 错误码 | 含义 | 常见原因 |
| --- | --- | --- |
| `-105` | 域名无法解析 | 主机名写错、DNS 不可用、地址填了不存在的域名 |
| `-102` | 连接被拒绝 | 目标端口没有服务在监听，或本地静态服务未启动 |
| `-118` | 连接超时 | 网络不通、目标主机不可达 |
| `-3` | 导航被主动取消 | 页面自身跳转导致，已忽略，不会展示失败态 |

失败页会同时显示错误描述与当前地址，可直接点「重试」就地重载，或「返回首页」回首页。

### 地址能打开，但应用里一直转圈或跳去系统浏览器

内嵌页按主机名白名单放行，白名单取「配置里那个地址的主机名」。`127.0.0.1` 与 `localhost` 是两个不同主机名：配置填 `http://localhost:2602`，网页内部跳到 `http://127.0.0.1:2602` 会被判定为跨站，转交系统浏览器。

处理：配置地址与网页内部链接保持同一主机名写法；确实需要跨站时，把目标地址改成配置里的写法。

### 网页里的下载、摄像头、麦克风、通知不可用

内嵌页会话默认拒绝全部权限申请与权限查询，并拦截下载；新窗口也一律交给系统浏览器。这是为了不让内嵌站点绕过应用往磁盘写文件或调用桌面设备。

内嵌页需要这些能力时，应调整网页端实现，而不是放宽应用安全策略。

### 端口被占用了怎么办

本地静态服务默认监听 `2602`，被占用时从该端口起向后自动避让，最多尝试 100 次，实际端口会回传界面。开启「端口占用提示」后，发生避让会弹框告知新端口。

注意：避让只影响服务本身，内嵌页地址不会自动跟着改。若页面指向 `127.0.0.1:2602` 而服务实际起在 `2603`，需手动把配置里的页面地址改成实际端口。

## 配置相关

### 配置改完没保存就关掉应用

界面改动经约 0.5 秒防抖后整体回写磁盘。正常关闭窗口、重启、退出、重置等动作都会先立即落盘，不会丢。极端情况下（如进程被强杀）防抖窗口内的最后一次修改可能未写入。

### 升级后配置和站点目录去哪了

打包版本首次启动会把可执行文件同级的旧目录 `fxwl-local` 迁到用户数据目录，迁移成功后写 `.migrated` 标记，之后不再重复迁移；迁移失败则回退旧目录继续启动，不会把应用卡在启动阶段。

若迁移后想回旧版本，旧目录仍在，旧版本会继续读它；两个版本的数据不会自动互通。

### 手工改配置文件导致应用起不来吗

不会。启动时会先按 `version` 迁移，再逐字段归一：缺失补默认值、数值收敛到区间、非法枚举回退默认值。但手工编辑前请先退出应用，避免内存态把磁盘改动覆盖回去。

### 配置页里找不到某个字段

配置页由 schema 驱动，只渲染已声明字段。目前未暴露、需要手工编辑的有 `app.store_name`、`app.url_list`。

## 展示行为相关

### 改了全屏、置顶、无边框没生效

这些是窗口创建参数，下次启动才应用。配置页修改后点「重启应用」即可生效。

### 开了强制置顶后其它程序抢不到焦点

「强制置顶」会周期性检查焦点，发现窗口失焦就抢回。它会干扰同机其它操作，只在展厅、大屏等独占场景开启，日常办公不要打开。

### 关了 HTTP 缓存后页面还是旧内容

`http_cache` 通过命令行开关关闭缓存，必须在应用就绪前设置，因此改完需要重启应用才生效。清理缓存请用底部动作栏的「清理缓存」。

### 开机自启设置后没有立刻出现

「开机自启」是立即注册或注销系统登录项的，但系统设置界面的列表刷新可能有延迟；以实际登录行为为准，不要在应用内反复切换。

## 快捷键相关

### `Alt+←` 或 `Esc` 没反应

- 这两个快捷键由主进程从内嵌页转发，只在客户端页生效。
- 鼠标焦点在内嵌页输入框、文本域或全屏控件内时，`Esc` 会交还网页自己处理，这是刻意保留的行为。
- 在首页或配置页按 `Esc` 不会触发后退。

### 鼠标侧键不能前进后退

侧键在 Electron 22 下没有系统级鼠标钩子，只能在页面内注入监听按浏览器习惯后退。网页自身拦截了 `mouseup`，或内嵌页尚未加载完成时，侧键不会生效。

## 构建与版本相关

### 为什么还用 Electron 22

为了继续支持 Windows 7。Electron 22 是最后支持 Win7 的发行线，且该版本内置 Node 为 16，主进程不能用 `structuredClone`、全局 `fetch` 等新 API。升级 Electron 会直接放弃 Win7，属于重大变更，需单独评估。

### 安装包提示未签名或未公证

本机打包不做 macOS 公证；CI 上仅在配置了 `APPLE_ID` 与 `APPLE_ID_PASS` 时才提交公证，且公证失败不阻断出包。Windows 安装包未做代码签名，系统可能给出未知发布者提示。详见[构建与打包](./build)。

### 开发模式能跑，打包后白屏

优先检查三处：

1. 构建产物是否完整，`out/renderer/index.html` 是否存在。
2. 内容安全策略是否拦了外部资源；CSP 只在构建期注入，开发模式不注入，两者表现会不同。
3. 渲染层是否在纯浏览器分支调用了 `window.doNative`；该对象在打包环境才有，调用前需判空。

## 仍然没解决

带上这些信息再排查会快很多：应用版本（底栏可见）、操作系统版本、复现步骤、失败页显示的错误码与地址、配置文件内容（注意先脱敏）。日志与配置目录位置见[配置说明](./config#一-配置文件)。
